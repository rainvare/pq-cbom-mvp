El problema

La criptografía que protege internet tiene fecha de caducidad

Un computador cuántico suficientemente grande romperá en tiempo polinomial (algoritmo de Shor) la criptografía asimétrica que hoy protege casi todo el tráfico seguro: RSA, ECDSA, Diffie-Hellman. No sabemos cuándo — pero migrar la criptografía de una organización tarda años.

🔓

Shor rompe lo asimétrico

RSA, ECDSA, ECDH y Diffie-Hellman caen en tiempo polinomial. Es matemática, no fuerza bruta.

⏳

Migrar tarda años

Identificar qué usa qué algoritmo, dónde y con qué prioridad es un proyecto de varios años.

📡

El riesgo ya empezó

Tráfico interceptado hoy puede guardarse y descifrarse después. No hay que esperar al Q-day.

Harvest now, decrypt later

Un adversario captura y almacena hoy datos cifrados con criptografía clásica, a la espera de un computador cuántico que los descifre mañana. Por eso el riesgo de un dato depende de cuántos años debe seguir siendo secreto, no solo de cuándo llegue el Q-day. Ese cálculo es el teorema de Mosca — y está en la demo.

La solución

Descubrimiento + clasificación determinista + modelo de riesgo

Un pipeline auditable, sin cajas negras ni decisiones en tiempo real. Tres collectors alimentan una base de conocimiento única, y el resultado es un inventario (CBOM) con prioridades accionables.

📂

Collector de código

Escanea el código fuente (regex o Semgrep AST) buscando uso de algoritmos criptográficos.

🔐

Collector de red (TLS)

Inspecciona versiones TLS y el certificado de un host con sslyze.

🛰️

Descubrimiento pasivo

Enumera superficie desde Certificate Transparency (crt.sh) sin tocar el objetivo, más TLS/cabeceras con autorización.

📚

Base de conocimiento

La fuente de verdad: cada algoritmo con su impacto cuántico (Shor/Grover), bits de seguridad, estado NIST, estándar FIPS/RFC y reemplazo recomendado. Separada de la detección.

📊

Modelo de riesgo

Agrega el inventario en preparación cuántica (% seguro), exposición HNDL, teorema de Mosca y una hoja de ruta por prioridad. Exportable a CycloneDX 1.6.

python -m pq_cbom.cli scan ./mi-repo --engine semgrep --output cbom.json

Escanea código fuente en 15+ lenguajes. El motor Semgrep evita falsos positivos de comentarios y strings.

python -m pq_cbom.cli scan-keys ./mi-repo

Parsea certificados y claves reales (PEM/DER/SSH) y extrae el tamaño de clave: distingue RSA-1024 de RSA-4096 y marca las claves cortas. Es la dimensión que una simple búsqueda de texto no ve.

python -m pq_cbom.cli scan-deps ./mi-repo

Lee manifiestos (package.json, requirements.txt, go.mod, pom.xml, Cargo.toml…) y encuentra la cripto que entra por librería aunque no aparezca ningún algoritmo en el código. Marca librerías abandonadas o con CVE conocida (pycrypto, elliptic<6.5.4, node-forge<1.0…).

python -m pq_cbom.cli scan-contracts ./contracts --fail-on high

Analizador de vulnerabilidades de smart contracts (Solidity) alineado con el SWC Registry: reentrancy, tx.origin, delegatecall, selfdestruct, aleatoriedad débil, overflow (<0.8), y el puente cripto ecrecover → ECDSA secp256k1 (vulnerable a Shor). Heurística estática para revisión humana.

python -m pq_cbom.cli scan-tls ejemplo.com --port 443

Reporta versiones TLS aceptadas y el tipo de clave del certificado del host.

python -m pq_cbom.cli scan-passive ejemplo.com --ct-only python -m pq_cbom.cli scan-passive ejemplo.com --authorize ejemplo.com

CT logs (certificados), DNSSEC (algoritmo de firma de la zona) y CAA salen vía resolver público, sin tocar el objetivo. TLS/cabeceras y JWKS (algoritmos de firma de JWT) sí lo contactan.

La parte que contacta al objetivo (TLS/cabeceras/JWKS) solo corre contra dominios autorizados explícitamente: esta herramienta evalúa tu propia postura cripto o la de un cliente con permiso, no sistemas de terceros.

python -m pq_cbom.cli risk cbom.json --shelf-life 15 --qday 10 --fail-on high python -m pq_cbom.cli scan ./repo --fail-on vulnerable # gate de CI python -m pq_cbom.cli export cbom.json --format cyclonedx --output bom.json

Riesgo agregado (incluye tamaño de clave: marca RSA-1024 y claves cortas), modo CI (--fail-on devuelve código 1 para romper el build) y export a CycloneDX 1.6.
